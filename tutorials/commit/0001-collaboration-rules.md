# 0001 Collaboration rules for human-AI changes

## 背景

`br1` 还处在很早期的阶段，但 AI 改代码的速度已经明显快过人类单纯靠记忆去跟踪变更的速度。

如果没有强约束，后面很容易出现几种问题：

- 提交信息只写“update”或“fix”
- 改动做了，但没人知道为什么这样做
- 说测试过了，但不知道测了什么
- 明明还有已知缺口，却没有写下来

这次改动不是产品功能本身，而是给后续所有产品改动先铺一条更清楚的协作轨道。

## 主要目标

把 `br1` 的协作规则写清楚，让后续每次非 trivial 的 AI 改动都能留下：

- 高信息量提交说明
- 真实验证记录
- 明确未覆盖项
- 一篇给新人看的提交教程
- 一个“做完就提交”的默认节奏

## 改动概览

- 在 `AGENTS.md` 中补充了强提交信息规则
- 明确了自动提交边界，要求在“一个清晰功能切片完成、验证完成、教程写完”后自动提交
- 增加了 `tutorials/commit/NNNN-*.md` 的规则
- 说明了当前仓库还没有独立 git 仓库时，如何先准备 commit 材料

## 关键知识

### 1. 不是每次提交都要很长，但每次提交都要高信号

真正重要的不是字数，而是有没有回答清楚：

- 为什么做
- 做了什么
- 怎么验证
- 还没做什么

### 2. 教程文件不是重复 commit message

commit message 是给快速浏览的人看的。  
tutorials/commit/NNNN-*.md 是给后来接手的人看的。

它应该帮助一个新人理解：

- 这次改动在产品或工程上解决了什么
- 改动牵涉了哪些关键约束
- 哪些地方故意没有做完

### 3. 自动提交不是“偷偷提交”

这里的自动提交规则有前提：

- 这个功能切片已经先和用户对齐
- 验证已经完成
- 教程已经写好

所以它不是越权，而是减少“明明已经做完还卡在最后一步”的摩擦。

## 验证

- 手工检查 `AGENTS.md` 中是否新增了：
  - 自动提交规则
  - 教程目录规则
  - 当前无 git 时的处理方式
- 手工检查 `tutorials/commit/0001-collaboration-rules.md` 是否已创建
- 建议执行：`pnpm check`

## 未覆盖项

- 这次没有初始化 git 仓库
- 这次没有真正创建 commit，只是先把协作规则和教程模板落下
- 后续真实功能提交时，还需要按这些规则继续新增 `0002-*.md`、`0003-*.md` 等教程
