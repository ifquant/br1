# 0501: add the first parallel-read surface

这次改动把 `P1-3.2` 从“模型里能表达双窗格”推进到“界面上真的能开出第二个阅读面板”。默认还是单阅读器，只有用户明确点开并行阅读时，才会把当前主窗格的书再开到副窗格里。

## 改了什么

- 在阅读页加了一个显式的“并行阅读”按钮
- 点开后，副窗格会复制当前主窗格正在看的书，而不是去挑一本文不同的书
- 主窗格和副窗格分别持有自己的 `controlRequest`、预览状态和进度状态
- 两个 `ReaderStage` 在宽屏时并排显示，窄屏时自动变成单列堆叠
- 关闭并行时，会把副窗格收回到空状态，主窗格继续保留原来的阅读位置
- 更新了 e2e 冒烟测试和对齐清单

## 这一步为什么要这样做

并行阅读最容易做坏的点，不是“能不能渲染两个组件”，而是“两个窗格是不是还在互相串门”。所以这一步先守住一个最重要的边界：**副窗格可以独立翻页，但不能把主窗格一起带着走**。

对初学者来说，可以把它拆成三层理解：

1. 先给页面一个开关
2. 再把同一本书开到第二个窗格里
3. 最后把两个窗格的翻页请求分开处理

顺序不能反过来。先做布局很容易把状态写乱，后面再拆会更痛。

## 没有包含

- 没有做副窗格单独选书
- 没有做目录/侧栏/书签的按窗格隔离
- 没有做 relocation sync
- 没有做主副窗格联动翻页
