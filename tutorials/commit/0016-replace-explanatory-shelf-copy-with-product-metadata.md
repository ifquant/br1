# 0016 Replace explanatory shelf copy with product metadata

## 背景

`Step 1` 已经把 `library` 从全局壳里半解耦出来了，但 shelf 自己的 header 里还残留一种很明显的“设计说明味”：

- 一块书架下面配一段解释句子
- 内容更像在告诉开发者“这里以后要做什么”
- 不像真实产品会对用户展示的 UI

这类文案在设计阶段有帮助，但在成品界面里会持续把页面拉回 demo 气质。

## 主要目标

- 去掉 shelf 级别的解释型说明文案
- 改成更接近成品产品界面的 metadata 表达
- 让 section header 更像工具系统的一部分

## 改动概览

- 更新 `BookshelfPreview.svelte`
  - 删除 `sectionHint`
  - 增加 `totalItems`
  - 用 `items + viewMode` 这种更像产品 metadata 的信息替代说明文案
- 更新 `library/+page.svelte`
  - 不再给 shelf 传空的说明文案占位

## 关键知识

### 1. 成品界面更喜欢“状态信息”，不喜欢“解释信息”

这次把 shelf header 从说明文案换成 metadata，本质上是在换一种信息类型：

- 说明信息：解释这块区域未来会做什么
- 状态信息：告诉用户这块区域现在是什么状态

成熟产品界面通常偏向后者，因为它不会打断用户，也不会让 UI 看起来像演示稿。

一个很好用的判断标准是：

- 如果这段文字在回答“这个设计为什么这样做”
- 那它多半不该出现在成品 UI

### 2. 用轻量 metadata 代替段落说明，是一种常见的产品化收口方式

像：

- `4 items`
- `grid`
- `list`

这种很轻的 metadata，既能保留结构提示，又不会把视觉重心从内容本身拉走。

这也是为什么很多成熟工具产品会在 section header 里放：

- 数量
- 模式
- 排序状态

而不是放一段解释句子。

### 3. 小步对齐时，优先删“看起来像注释”的 UI，是很高回报的一刀

这一步改动不大，但回报高，因为它直接处理的是气质问题：

- 不一定让页面变“更炫”
- 但会让页面更像成品

这类调整特别适合放在中期收口阶段，因为它能快速把“设计稿味”压下去。
