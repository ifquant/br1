# 0020 Polish library view mode weight

## 背景

前几步已经把 `library` 的大骨架拉近了：

- 页面层级更像阅读器主界面
- toolbar 更薄
- bookshelf 更有列数节奏
- 单张书卡也比之前安静很多

到这个阶段，剩下的差距往往不是“大错”，而是系统感不够统一。

最容易露馅的地方通常有三个：

- section header 像一套系统，还是几块临时拼起来的 UI
- `grid / list` 模式切换有没有同一种光学重量
- import tile 是不是 still 像一个 CTA 卡，而不是 shelf 里的一个入口

所以这一步做的是整体 polish，不是另起一轮重做。

## 主要目标

- 统一 section header 的信息密度
- 让模式切换控件更像阅读器工具系统
- 给 list 模式更清楚的“行项感”
- 把 import tile 再压回 bookshelf 系统里

## 改动概览

- 更新 `src/lib/components/library/BookshelfPreview.svelte`
  - 收紧 `tools` 间距和 `shelf-meta` 的字号
  - 给 metadata 增加更轻的分隔点
  - 收紧 `grid / list` 模式 pill 的 padding、背景和 active 态
  - 给 list 模式书项加轻分隔线和更稳定的行节奏
  - 给 import tile 增加更系统化的 hover 和更轻的 plus 权重

## 关键知识

### 1. 很多“更像成品”的感觉，来自统一的光学重量，而不是更多组件

设计收口到了后期，常见误区是：

- 觉得哪里不够像，就再加一个新组件
- 或者再做一层更复杂的装饰

但成熟产品更多靠的是统一的光学重量：

- 字号是不是成组变化
- 间距是不是同一节奏
- active 态是不是和整个界面的阴影、边框、背景同一个体系

这一步其实没加多少新结构，主要是在调：

- `tools` 的 gap
- `meta` 的字号和分隔
- 模式 pill 的 padding 和 active 背景

这类修改看起来小，但能快速把“几个零散组件”压成“同一个系统里的控件”。

### 2. list 模式不一定要重做组件，先加“行项感”通常就够值

很多界面做 list 模式时，会一上来就做一套全新的 list item 组件。

但在对齐阶段，更高回报的办法 often 是先补最关键的行项信号：

- 垂直节奏
- 底部分隔线
- 左右信息对齐

只要这几个信号建立起来，用户就会先把它读成“列表”。

这一步给 list 模式书项加了轻分隔线和底部 padding，本质上就是在补这个信号。

这是一种很实用的小步策略：

- 先让模式感成立
- 再决定有没有必要拆全新的组件

### 3. CTA 卡和系统入口卡，区别通常不在文案，而在存在感

同样是“导入书籍”，它既可以看起来像：

- 一个高存在感 CTA
- 也可以像 bookshelf 里的一个系统入口

两者差别常常不在文字，而在：

- hover 是否太跳
- 边框是否太重
- plus 是否太大
- 背景是否像单独设计的卡

这一步把 import tile 再压轻一点，就是为了让它更像书架的一部分，而不是一块单独发声的广告位。
