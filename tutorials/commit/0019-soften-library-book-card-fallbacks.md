# 0019 Soften library book card fallbacks

## 背景

经过前几步之后，`library` 的整体框架已经比最开始更像 `Readest` 了：

- 壳层干扰少了
- 顶部工具条更薄了
- bookshelf 的列数和留白节奏也稳定了

这时最显眼的问题就落到了单张书卡上。

尤其是假封面（fallback cover）有两个典型风险：

- 做得太花，会比真实封面还抢戏
- 做得太重，会让整张书卡看起来像设计稿，而不是产品里的临时占位

所以这一步的目标不是“把书卡做得更有设计感”，而是让它更安静、更系统。

## 主要目标

- 降低 fallback cover 的视觉噪音
- 收紧标题、作者、状态信息的层级
- 让 hover 动作位更接近工具型控制，而不是概念按钮

## 改动概览

- 更新 `src/lib/components/library/BookshelfPreview.svelte`
  - 收轻封面背景、边框和阴影
  - 调整 fallback cover 的内边距、标题字重、字号和颜色
  - 为 list 模式加单独的 fallback cover 紧缩样式
  - 收轻 hover 动作位的尺寸、阴影和出现动画
  - 压缩书卡下方标题、作者、状态行的字号和间距

## 关键知识

### 1. 占位封面最常见的错误，不是太丑，而是“太会表现自己”

在真实产品里，fallback cover 的职责不是当设计主角，而是：

- 在没有真实封面时兜底
- 保持书架节奏不塌
- 让用户还能识别书名和作者

所以它通常应该满足三件事：

- 可读
- 中性
- 不抢真实内容

如果占位封面用了太强的纹理、太重的阴影、太激进的字体对比，它虽然“看起来更设计”，但会破坏整个 bookshelf 的主次关系。

这也是为什么这一步做的是“降噪”：

- 更轻的背景渐变
- 更轻的阴影
- 更克制的标题字重
- 更淡的作者信息

### 2. 书卡元信息的收口，本质上是在决定“用户先读哪一行”

书卡底部常见的信息至少有三层：

- 书名
- 作者
- 状态 / 进度

如果这些字级太接近，用户会觉得一坨文字都在争注意力。

这一步通过压缩字号和间距，实际上是在做视觉优先级：

- `strong` 保持第一层
- `span` 退到第二层
- `small / em` 退到第三层

一个很实用的判断方法是：

- 把页面缩远一点看
- 如果你还一眼能看出哪一行是“书名”
- 那层级通常就还算成立

### 3. 没有正式 icon 时，也可以先把 hover 动作位做成“工具”而不是“装饰”

我们现在 hover 动作位还是占位字形，不是真实 icon。

但这不代表它只能先放着不管。

即使是占位阶段，也可以先处理这些问题：

- 大小是不是太抢眼
- 阴影是不是像漂浮按钮
- 出现动画是不是太夸张

这一步把动作位收得更小、更轻，并加了轻微位移动画，目的就是先让它像工具控制的一部分。

这样后面替换成真正图标时，通常不需要再推翻整个 hover 语言。
