# 0349 - 让移动端 reader 首屏先看到正文

这次修复处理的是 reader 在窄屏下的视觉顺序问题：移动端打开书籍后，用户第一屏先看到目录、书卡和工具栏，正文被推到下面。

对阅读器来说，这个顺序是反的。目录、搜索、书签和 bridge 都是辅助层；移动端空间更小，首屏应该先让用户确认“书已经打开，正文可以读”。如果用户必须先滚过一段侧栏 chrome 才看到正文，阅读器会像管理后台，而不是阅读器。

## 改了什么

- 在 reader 页面窄屏布局里，把 `.reader-stage` 排到第一位。
- 把 `.reader-sidebar` 排到正文之后。
- 把右侧 bridge 占位区继续放在最后。
- 桌面三栏布局不变，仍然保持左侧目录、中间正文、右侧 bridge。

## 为什么只改 CSS 顺序

DOM 顺序现在是 sidebar、stage、bridge。桌面下这个顺序很好，因为 grid 有三列，视觉上自然成立。

问题只出现在 `max-width: 960px` 后：grid 变成单列，但 DOM 顺序没有变化，于是 sidebar 先占据移动首屏。

这类问题不需要重写组件，也不需要移动 Svelte 结构。CSS 的 `order` 正好表达“窄屏时视觉顺序不同”：

- 桌面：结构顺序服务三栏布局。
- 移动：视觉顺序服务阅读任务。

## 一个小知识点

响应式设计不是“把桌面列堆成一列”就结束了。堆叠顺序本身就是设计决策。

如果一个页面有主任务和辅助信息，移动端通常应该先展示主任务，再展示辅助信息。对 br1 reader 来说，主任务就是正文；目录和 bridge 是读书过程中的工具，不应该抢第一屏。
