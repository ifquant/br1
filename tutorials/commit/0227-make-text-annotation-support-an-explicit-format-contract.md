# 0227: 把正文批注支持做成显式格式契约

这次没有直接去做 “让所有 secondary formats 都能记笔记”，而是先把一个更基础的产品问题收掉：

- 哪些格式支持正文文本批注
- 哪些格式当前根本不支持

在这之前，`notes` 面板对所有格式几乎都说同一句话：

- “先在正文里选中一段文本，再把它存成当前书的笔记。”

这在 `EPUB/FB2/MOBI/AZW3` 这类 reflowable 文本书上还能成立，但对当前的：

- `TXT`
- `CBZ`

其实是误导。

## 这一步为什么值钱

`P0-3` 的目标不只是“有 notes/bookmarks 代码”，而是要把 annotation 变成正式产品能力。

做这件事的第一步，不是硬上所有格式的笔记实现，而是先把支持边界说清楚：

- 支持的格式，要给真实入口
- 不支持的格式，要给明确降级

否则用户会一直遇到这种半成品体验：

- 面板看起来像能记笔记
- 但实际上永远选不中
- 或者切书以后还残留上一本书的选区

这种体验比“明确说当前不支持”更差。

## 这次实际做了什么

### 1. 把正文批注支持抽成共享 helper

这次在 `formats.ts` 里新增了显式 helper：

- `supportsTextAnnotationsForFormat()`
- `getTextAnnotationSupportMessage()`

当前契约很清楚：

- `CBZ`：不支持正文文本批注
- `TXT`：当前也不支持正文文本批注
- 其它现有文本型 reader format：继续保留原有 notes 行为

这里故意没有把 `TXT` 硬说成支持，因为当前还没有把它做成真正可持久化、可跳转、可 reopen 的文本笔记系统。

### 2. notes 面板不再对所有格式说同一句话

`ReaderSidebar` 现在会按当前格式切换 notes 面板的说明、状态 chips 和主按钮：

- 支持正文批注的格式：
  - 仍然显示选区预览
  - 按钮随选区启用
- `TXT/CBZ`：
  - 显示“当前格式暂不支持正文批注”
  - 展示明确原因
  - 主按钮禁用

这让 notes workspace 从“有时像坏了”变成“产品边界明确”。

### 3. 清掉不支持格式上的旧选区残留

仅仅改文案还不够。

如果用户先在一本 `EPUB` 上选中一段文本，再切到 `TXT` 或 `CBZ`，旧的选区对象如果还挂在 controller 里，notes 面板还是会看起来像能记笔记。

这次在 route 层加了一个小但必要的收口：

- 当前格式不支持正文批注时，主动清空选区状态

这样切格式后不会再继承上一本书的假选区。

### 4. 用 web smoke 锁住显式降级

新增的 smoke 不再只测“能不能打开 `TXT/CBZ`”，还会继续验证：

- 切到 notes tab
- 页面显示明确的格式级降级文案
- “当前格式暂不支持批注”按钮处于 disabled

这就把这条产品契约锁成了可回归行为，而不是一次性的 UI 文案。

## 为什么这一步先做“显式不支持”，而不是立刻给 TXT 做笔记

因为现在 `TXT` 虽然已经有：

- 真实阅读面
- 滚动进度
- restore

但还没有形成完整的文本批注链路：

- 稳定的选区定位
- 持久化定位键
- reopen 后的定位 / 聚焦
- notes overlay / focus 行为

如果这一步硬把 `TXT` 的“可选中文本”接成半吊子 notes，会比当前的显式降级更脏。

更合理的顺序是：

1. 先把支持边界说清楚
2. 再单独把 `TXT` 的文本批注做成正式能力

## 结果

`Annotations and Highlighting` 这一行虽然还不能改成 `Completed`，但产品状态已经更像一个真实系统：

- 支持边界开始显式化
- 不支持的格式不再冒充支持
- notes workspace 的行为开始按格式收口

这比继续把“看起来一样、实际上不一样”的 notes UI 往前堆，要更接近正式产品能力。

## 这一步没有包含

- 没有让 `TXT` 真正支持可持久化的文本笔记
- 没有让 `CBZ` 支持漫画级 annotation
- 没有开始做 highlight 的正式产品化
