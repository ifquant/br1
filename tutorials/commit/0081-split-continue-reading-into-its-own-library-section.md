# 0081 把 Continue Reading 升级成独立书架 section

这次提交只动 `library` 的展示层，不改后端持久化结构。

前两刀已经让书库具备了这些能力：

- `reader` 会把阅读状态回写到 `library.json`
- `library` 也会按最近阅读排序

但如果只是“排序优先”，用户看到的仍然只是一整个大书架。  
这次补的是更接近成熟阅读器的展示方式：

- 最近读过的书，单独放进一个 `继续阅读` section
- 完整书库仍然保留在下面

这样“继续读什么”和“我总共有些什么书”这两件事，在 UI 上就分开了。

## 这次能学到的 2 个编程点

### 知识点 1：排序和分组不是一回事

很多产品刚开始会把“重要的东西排前面”当成“产品结构已经完成”。  
其实这两者差很多：

- **排序**：数据还是一个集合，只是顺序变了
- **分组/section**：数据被赋予了更明确的产品语义

这里的差异就是：

- “最近阅读排在前面”
- 和
- “继续阅读是一个独立区域”

后者用户理解起来会快很多。

### 知识点 2：展示层最好从持久化层投影出更轻的 UI 模型

这次没有直接在组件里处理 `PersistedLibraryBook`，而是继续用：

- `PersistedLibraryBook -> ShelfBook`

这层映射。

这样做的好处是：

- 书库持久化结构可以慢慢演进
- UI 组件仍然只关心自己要显示什么

这是一种常见的“领域模型 -> 展示模型”的分层方式。

## 这次还没做什么

- `继续阅读` 还没有独立视图模式控制
- 还没有按阅读活跃度、 pinned books 等更复杂规则筛选
- `你的书库` 仍然包含 `继续阅读` 里的书，也就是会有重复出现

这次只先完成最直接也最有产品感的一步：

`最近读过的书，开始拥有自己独立的 section`
