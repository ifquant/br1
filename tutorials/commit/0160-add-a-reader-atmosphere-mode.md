# 0160: 给 reader view menu 补阅读氛围模式

## 这次改了什么

前两刀我们已经让 `⋯` 菜单开始承担真正的阅读设置入口：

- 阅读宽度
- 界面显隐

但它还缺一个很典型的阅读器设置维度：

- 阅读氛围

所以这一步继续只做纯 UI 切片：

- `纸白`
- `暖纸`
- `柔和`

对应的是 `ReaderStage` 外层舞台背景的三档风格变化，并把这个偏好记到本地。

## 为什么这一步只改舞台背景，不改正文内部主题

因为这里的目标仍然是：

- 增强 view menu 的真实感
- 但不去碰 `ReaderViewport` 内部的渲染和排版细节

所以这一步的边界非常明确：

- 改外层舞台氛围
- 不改正文书页本身

这让它既有用户可见差异，又不会干扰 EPUB/PDF 渲染链路。

## 这次实现上的关键点

### 1. 用一个枚举把菜单层和样式层串起来

这次新增了：

- `ReaderAtmosphereMode = 'paper' | 'warm' | 'soft'`

然后：

- `ReaderHeaderBar` 只负责展示菜单选项
- `ReaderStage` 负责把模式映射到背景变量

这样数据流仍然是清楚的。

### 2. 背景差异通过 CSS 变量统一落到 `canvas`

这一步没有给每种模式复制整段 `canvas` 样式，而是让：

- `.reader-stage` 提供 `--reader-stage-fill`
- 不同 atmosphere mode 只改这个变量
- `.canvas` 统一消费这个变量

这比三套重复样式更容易维护。

## 这次能学到的编程知识

### 知识点 1：视觉模式切换适合用“变量 + 修饰类”组织

如果你直接给每种模式写一整套组件样式，后面很容易重复和失控。  
更稳的结构通常是：

- 一个基础组件
- 少量修饰类
- 样式差异落到变量上

### 知识点 2：先从外围氛围切换开始，比直接做深层主题更安全

阅读器的主题系统通常很深，会影响：

- 书页背景
- 文本颜色
- iframe 内容
- PDF viewer

而这一步只改外围舞台，就能先把菜单做出来，同时保持风险可控。

## 还没做的事

- 这还不是正文级别的主题系统
- 还没有专项自动化回归直接切换三档阅读氛围
- `view menu` 里仍然缺字体、分页等更深的阅读设置
