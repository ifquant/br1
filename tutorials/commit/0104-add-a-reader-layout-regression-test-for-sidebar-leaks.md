# 这次提交讲了什么

这次不是修 UI，而是把一个很容易反复回来的布局 bug 收成了桌面自动化回归：

- 打开一本书后
- 真正渲染出来的正文页面
- 必须落在 `reader stage`
- 不能跑到 sidebar 左侧或左下角

这类 bug 靠截图很容易“看出来一次，下一次又忘了”，所以最值钱的是把它变成能自动失败的几何断言。

## 你能学到的具体知识

### 1. 视觉错位问题也可以写成几何规则

不是所有 UI bug 都要靠像素截图比对。  
像这次这种问题，本质上可以变成几条简单规则：

- 正文页面左边不能小于主舞台左边
- 正文页面不能跑进 sidebar 的列
- 正文页面不能掉到主舞台下半区才开始出现
- 正文页面尺寸不能小得离谱

一旦这些规则被写进桌面测试，后面谁再把布局改坏，CI 就会先报。

### 2. 桌面 WebView 里的复杂组件，最好直接量真实 DOM 的矩形

这次不是只测：

- “reader window 打开了”
- “foliate-view 存在了”

而是继续往下一层量：

- `.reader-stage`
- `.reader-sidebar`
- `foliate-view` 里真正的页面 iframe / paginator

然后比较它们的 `getBoundingClientRect()`。

这种做法特别适合：

- 多栏布局
- overlay panel
- iframe / shadow DOM 渲染
- “元素存在，但位置不对”的 bug

## 这次为什么放在 WDIO 桌面测试里

这个问题只在真正的桌面阅读窗里最明显。  
所以把它放进现有的 Tauri WebDriver smoke 最合适：

- 路径真实
- 窗口真实
- 布局真实

这样以后你再问“这类问题能不能自动确认”，答案就是：能，而且已经开始这样做了。
