# 0729 - 按记录回显与操作脚注批注

## 背景

C8C 能保存脚注选区。C8D 补上从已保存批注返回当前摘录的方向，让阅读者
在重新打开脚注后仍能看到高亮和笔记，并能分别处理同一位置的多条记录。

## 改动概览

- 复用原始文本节点与 UTF-16 偏移对应关系，反向映射持久化 CFI。
  批注跨出摘录时，只绘制经过双向验证的交集，并明确标记为部分原文。
- 先拒绝其他章节的 CFI，再加载一个原始章节文档处理当前批次。
  畸形、无法定位、被清理掉的文字、来源变化和过期请求都不能产生绘制。
- 弹窗复用原生 Overlayer，装饰层是正文根的兄弟节点。滚动、边框、尺寸
  变化后的坐标换算只影响绘图，命中测试仍使用视口坐标。
- 每条批注按 ID 绘制。点击或键盘选择可查看原有笔记记录；编辑和删除
  仍交给主阅读窗格的笔记控制器，不导航到另一个界面，也不创建新存储。
- 正文批注改用已加载图层上的同步操作，避免原生异步 addAnnotation
  在换书后误操作新图层。绘制前要求书源、笔记所属库与已恢复快照一致。
- 区分导航与布局重排；窗口缩放产生的 anchor 事件不再关闭脚注。
  批注面板与预览共用本阅读窗格可见区域内的外层容器，左右或上下并行
  都不跨入另一窗格；短窗口保留原生滚动，短脚注不被最小高度撑出空白；
  不透明底色避免正文透过面板，忙碌状态不再移走编辑按钮的键盘焦点。

## 关键知识

1. 位置相同不等于记录相同。CFI 描述范围，ID 描述笔记；用 CFI 当图层
   主键会让同一段文字上的两条笔记互相覆盖，删除时也无法区分。
2. 检查一次身份再进入异步函数，并不能保护函数内部后续的修改。这里
   复用同步 Overlayer，把校验和修改放在同一个不可被异步任务打断的步骤。
3. DOM 范围交集需要比较正确的起止端点。元素端点与文本端点可以表达
   同一范围，应先规范化，再验证原始节点和偏移，而不是仅比较可见文字。
4. iframe 有独立的 JavaScript 全局对象。它创建的 Range 不是主页面
   Range 的实例，验证时必须使用所属文档的构造器。另一个独立边界是
   XHTML 与 HTML 的序列化：相同段落可能多出 xmlns 或使用不同的空标签
   形式。统一到 HTML 序列化后再比较结构，不能因为文本相同就放行。
5. 布局状态更新与用户导航不是同一事件。原生 View 会丢掉重定位原因，
   因此复用 renderer 已有的原因区分，不能把所有 readerstate 更新都当作
   离开当前脚注。批注与选区仍由原来的请求和 DOM 节点持有。
