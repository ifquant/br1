# 保留正文的双向文字与代码排版语义

## 背景

`S2-R04C` 的逐提交表实际包含 34 项，旧摘要只列了 31 项。本次先完成 `S2-R04C1`，处理 `69599e2bc`、`44953f568`、`2f9262e02` 的代码连字和双向文字兼容，并判定两个章节跳过链接修复的适用性。

## 主要目标

让代码操作符保持字面形态，让波斯语和阿拉伯语中被误用作半空格的 RLM 按上游规则参与正确排版，同时保留真正的方向标记。

## 改动概览

- EPUB 的 `pre`、`code`、`kbd` 禁用连字；TXT 围栏代码使用相同策略，普通正文不受影响。
- HTML/XHTML 仍先通过既有 DOMPurify 安全清理，然后只处理正文文本节点中的 RLM。
- 两侧符合上游阿拉伯字符范围的连续 U+200F，替换为等长的 U+200C；包含组合附加符与表现形式，排除两类阿拉伯数字。
- 代码、样式、属性、SVG 和 MathML 保持原文；边界或拉丁文字旁的方向标记也保持原样。
- `6626db967` 和 `86493e801` 修复 Readest 注入的章节跳过链接。br1 没有该注入路径，本次标为 not-applicable；这不表示完整的可访问性能力已对齐。

## 关键知识

1. RLM（U+200F）影响双向文字排序，ZWNJ（U+200C）控制字符是否连写。两者不可全局互换。本次使用明确的上下文条件，且替换前后 UTF-16 长度相同。
2. 对整个 HTML 字符串做排版替换可能误改属性或代码。安全清理之后遍历正文文本节点，可以复用浏览器的实体解码并维持边界。
