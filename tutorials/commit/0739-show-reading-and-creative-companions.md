# 0739: 展示真实阅读能力与创作方向

## 背景

原 README 用较长的生态架构介绍项目，真实阅读器出现得过晚。用户希望根据
创业讨论稿 v0.11 重写英文介绍，只介绍 br1，突出潜力和算力需求，并补充
古代兵书到战争游戏、格林童话到故事动画两种概念 GIF。随后又要求展示基础
阅读能力，画面不能使用中文书籍或临时测试数据。

## 主要目标

将介绍顺序调整为真实阅读器、现有能力、未来体验、概念演示、算力支持、
构建方法。愿景不能被写成已经完成的自动生成功能。

## 改动概览

- README 移除占据主线的七类图谱和六阶段生态路线，保留阅读优先、个人
  积累、选择性共享、来源与改编分开，以及阅读和实践之间的往返。
- 用真实运行的 br1 web reader 打开英文《Pride and Prejudice》，展示正文、
  选区操作、保存的英文阅读批注、排版设置和两个不同章节的并行阅读。
  README 不再展示旧的中文书库和并行阅读截图；原文件没有删除。
- 新增两支原创代码绘制的 GIF，持续显示概念标识。它们没有调用 br1 的
  自动生成流程，也不是历史模拟、模型效果评测或儿童教育效果证明。
- HTML 回放提供暂停续播、重播、故事切换和随分镜更新的可读文字，窄屏
  不必只依赖缩小的画布；导出脚本创建新目录而不清空现有数据。
- 说明持续 token/API 额度与算力支持将用于长书处理、上下文辅助、多模态
  创作及反复检查修订，不虚构当前消耗量、成本预算或学习收益。
- 媒体说明记录原书来源、截图方式、英文批注来源与复现命令。外部查询和
  翻译会把提交的词句发送给所选服务商，README 已明确提示。

## 关键知识

1. 动画截图必须使用确定的时间。实时 `requestAnimationFrame` 会覆盖人工
   指定的分镜，因此录制先暂停实时播放，再以固定时间采样；分镜编号断言
   能及时暴露错误。暂停后恢复保留播放位置，重播才从零开始。
2. GIF 的帧延迟单位是百分之一秒，不能准确表达每帧 1/12 秒。240 帧中使用
   80 个 90ms 和 160 个 80ms 延迟，累计刚好 20 秒；统一调色板减少帧间颜色
   漂移，也让压缩可以保留大部分未变化区域。
3. 真实界面截图和概念动画需要不同的证据说明。截图脚本只提供原书字节，
   不伪造服务响应、不替换 DOM/CSS；选区走浏览器 Range 和 selectionchange，
   笔记通过原有提示框保存。概念动画则明确标为作者编排的未来体验。

## 验证

- `node docs/demos/capture-reader-screenshots.mjs /tmp/br1-pride-and-prejudice-text.epub`
  完成五张真实阅读截图，断言正文目标、选区工具、保存的英文笔记与并行
  书籍就绪；最终两窗格分别展示 Chapter I 与 Chapter II。
- `node docs/demos/render-reading-concepts.mjs /tmp --posters` 与
  `python3 docs/demos/encode-reading-concepts.py <frames-dir> docs/images`
  完成动画录制和编码。实际 Python 使用本机 Codex 依赖运行时中的 Pillow。
- Pillow 检查两支 GIF 均为 1200x720、240 帧、20,000ms、无限循环，场景内
  两个采样时间的像素存在变化；并行截图两侧正文区域均非空白。
- Node 本地 Markdown 链接检查：11 项均存在；`git diff --check` 通过。
- 导出脚本在不存在的输出父目录中创建独立子目录；未知参数按预期报错。
  暂停续播、重播、键盘操作、故事切换及窄屏 44px 控件检查通过。
- 人工查看正文、选区、批注、设置、并行截图与概念关键帧；桌面和窄屏
  HTML 预览已采样。GIF 内小字号不因缩放自动变得可读，因此 HTML 回放
  另有同步文字版，GIF 本身仍需按原尺寸检查细节。
- Terra high 任务审查与来源修复复审通过；Astra high 整体闭环核对最终通过。

过程中修正了实时播放覆盖采样、河流越过地图边界、文字溢出和标记裁切。
整体审查还发现童话来源卡片混入了原创说明，已改为核实过的开篇原文摘录；
画布和可读文字版复用同一份摘录常量，再重新导出，避免两个版本的归属漂移。
截图准备阶段使用的书籍段落首字为大写 IT，匹配已改为稳定的原文片段；
并行页还增加了真实正文就绪等待，并选用有正文的 Chapter II。
