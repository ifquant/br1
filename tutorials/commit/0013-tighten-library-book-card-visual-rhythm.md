# 0013 Tighten the library book-card visual rhythm

## 背景

前两刀已经把 `library` 的整体 frame、header 和书架密度拉近到 `Readest`，但单张书卡 still 有一个明显问题：

- 更像“占位展示卡”
- 不像真正的阅读器书架条目

尤其是封面 fallback、标题排版、状态行和 hover 动作位这几块，还没有形成 `Readest` 那种克制的书卡节奏。

## 主要目标

- 继续把单张书卡往 `Readest` 的视觉语言压
- 让封面即使没有真实图片，也更像书而不是色块
- 收紧底部元信息和状态行的密度
- 给书卡加上更轻的 hover 动作位，减少“静态说明卡”感

## 改动概览

- 重写 `BookshelfPreview.svelte` 中的封面 fallback：
  - 封面内部加入书名和作者排版
  - 更像 `Readest` 的书封占位，而不是单纯背景块
- 增加轻量的 `cover-actions` 视觉占位
- 收紧书卡文字层级：
  - 标题更硬地单行截断
  - 作者更轻
  - 状态行更薄、更克制
- 微调 section header 和卡片 gap，让整体节奏更像阅读器书架

## 关键知识

### 1. 书卡像不像书，很多时候取决于“封面内部排版”，不取决于背景纹理

如果没有真实封面图片，最容易偷懒的做法就是：

- 放一个渐变块
- 再在卡片外面写标题和作者

这样虽然能占位，但不会有“这是一本到可阅读的书”的感觉。

更接近真实产品的做法是：

- 让 fallback cover 自己就带封面内部排版
- 书名和作者都住在封面里
- 封面外部的信息只保留更克制的一层元信息

这会显著减少“假卡片感”。

### 2. 阅读器书架的状态信息应该像注脚，不应该像副标题

这次把状态行压得更轻，是因为在阅读器里：

- 封面是主角
- 标题是第二层
- 进度 / 状态只是注脚

如果状态文本太粗、太大、太显眼，视觉重心就会从“看书”变成“看说明”。

所以一个很实用的规则是：

- progress / status 用更小字号
- 更弱颜色
- 尽量压在同一行

这样用户先看到的是书，而不是信息标签。

### 3. hover 动作位的意义，不只是交互，而是“产品气质”

这次加的 `cover-actions` 还只是视觉占位，没有真实逻辑。

但它已经有一个重要作用：

- 让卡片看起来更像可操作对象
- 更接近成熟桌面阅读器里的“可点、可管理、可继续展开”的书架项

也就是说，hover 元素有时候不仅是为了功能预告，也是为了把组件从“静态展示物”推向“交互型产品对象”。
