# 0021 Upgrade library header assets

## 背景

前面的几轮对齐，已经把 `library` 的整体节奏压得比较接近 `Readest` 了。

但有一个地方会持续暴露“这还是 wireframe”：

- 搜索区是文字占位，不是真输入框
- 右侧按钮是字符，不是真图标

这类问题很特殊：

- CSS 再怎么调，也只能让它“更像”
- 但只要还在用 `⌕ / + / ◫ / ≣` 这种字符占位
- 顶部就始终会带着很明显的草图感

所以这一步的目标不是加逻辑，而是补真实视觉资产层。

## 主要目标

- 把搜索区从文本占位升级成真实输入框形态
- 把 toolbar 按钮从字符占位升级成真实 SVG 图标
- 继续保持这一步只做视觉资产，不引入真实搜索逻辑

## 改动概览

- 更新 `src/lib/components/library/LibraryHeader.svelte`
  - 用真实 `input[type="search"]` 替代只读文本占位
  - 给搜索图标改成内联 SVG
  - 给右侧三个 toolbar 按钮改成内联 SVG 图标
  - 调整搜索框 padding、背景和 placeholder 颜色
  - 保留 `readonly`，明确这一步只升级视觉资产，不做行为接线

## 关键知识

### 1. 当界面还处在“像 wireframe”阶段时，优先替换 toolbar 资产，回报很高

页面里最常暴露“还没做完”的位置 usually 是：

- 顶部工具条
- 搜索框
- 图标按钮

原因很简单：

- 这些元素是高频、全局、第一眼就看到的
- 用户对它们的成熟度预期也最高

所以很多时候，哪怕数据和逻辑还没接好，先把 toolbar 的资产层做真，整体完成度都会明显上升。

这一步就是这个思路：

- 搜索框先变成真输入框
- 图标先变成真 SVG
- 行为仍然留在后面

这是一个很常用的产品化小步策略。

### 2. 没有图标库时，内联 SVG 往往比字符占位更稳

如果暂时不想引入额外依赖，一个很实用的办法就是直接写内联 SVG。

相对字符占位，它有几个明显优点：

- 线条粗细可控
- 光学重量可控
- 不会受字体差异影响
- hover、大小、对齐更稳定

而且对这种少量固定图标来说，内联 SVG 很适合：

- 不需要再引一个 icon package
- 也不用到处找资源文件

你只需要保证：

- `viewBox` 一致
- stroke/size 风格尽量一致

这样 toolbar 的系统感就会比字符占位强很多。

### 3. 真实输入框形态，不等于必须立刻接真实逻辑

这一步把搜索区换成了真 `input`，但仍然保持 `readonly`。

这么做的意义在于，把“视觉资产层”和“行为逻辑层”分开推进：

- 先做对长相
- 再做对行为

这是很有价值的分层方式，因为：

- 不会为了接逻辑打断当前视觉对齐节奏
- 也不会一直卡在“等功能好了再把 UI 做真”

一个常见误区是把“真输入框”误解成“必须立刻接搜索逻辑”。其实不需要。

只要你明确：

- 当前这是视觉升级
- 行为后续接

这就是一个合法而且高回报的小步。
