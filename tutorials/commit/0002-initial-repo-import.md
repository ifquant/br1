# 0002 Initial repo import for br1

## 背景

`br1` 之前还不是一个独立的 git 仓库。

在真正开始做产品实现之前，先把当前项目骨架、计划文档、协作规则、Tauri/Svelte 壳子、样例资源和辅助脚本纳入版本控制，可以让后续每一步演进都有可追踪的起点。

这一步的重点不是“做新功能”，而是把项目的起跑线固定下来。

## 主要目标

- 初始化 `br1` 的独立 git 仓库
- 把当前 agreed 的源码、文档、配置和样例数据纳入版本控制
- 排除依赖目录、缓存、编辑器状态和编译产物
- 为后续高质量 AI 提交建立一个干净的起点

## 改动概览

- 初始化了 `br1` 的 git 仓库并使用 `main` 作为默认分支
- 更新 `.gitignore`，排除 `node_modules*`、`.svelte-kit*`、编辑器状态、Python 缓存和构建产物
- 保留并纳入：
  - `src/`
  - `src-tauri/`
  - `static/`
  - `pydemo/`
  - `prompts/`
  - `tutorials/`
  - 计划、协作和配置文件

## 关键知识

### 1. 初始化提交不是“随便全丢进去”

初始化提交的质量会直接影响后面所有提交的可读性。

如果一开始就把依赖、缓存、IDE 状态和临时产物混进去，后面仓库会一直脏，AI 和人都更难判断什么才是真正的改动。

### 2. `pydemo/` 被有意保留

这次没有把 `pydemo/` 排除掉，因为你明确说过这部分也要纳入版本控制。

这意味着样例 `epub/pdf`、辅助 Python 脚本和相关 demo 数据都被视为项目资产，而不是本地临时文件。

### 3. 协作规则从第一提交就开始生效

这次提交不只是“把文件放进 git”。

它同时把：

- `AGENTS.md`
- `TODOS.md`
- `tutorials/commit/`

这些协作资产一起放进仓库，确保以后每次 AI 提交都可以沿着同一套规则继续走。
