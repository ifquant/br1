# 0005 Harden commit tutorial rules so each slice also teaches something

## 背景

`br1` 的协作规则已经要求：

- 每个清晰切片完成后自动提交
- 每个非 trivial 提交都要配一篇教程
- commit message 必须写清楚目的、改动、验证和未覆盖项

但之前还有一个空档：教程虽然有了，却没有被强制要求“必须教会人一点具体的编程知识”。

这会带来一个问题：教程可能只是把 diff 换种说法重写一遍。这样虽然记录了“做了什么”，但对学习帮助不够。

## 主要目标

- 把“教程必须包含具体知识点”写进 `AGENTS.md`
- 补强已有教程里的 `关键知识`
- 让之后每个提交教程都更像学习材料，而不是改动摘要

## 改动概览

- 更新 `AGENTS.md`，明确要求每篇非 trivial 教程都必须包含 1 到 2 个与当前提交直接相关的具体编程知识点
- 细化了 `关键知识` 的预期，要求它解释边界、工具链行为或实现取舍，而不是泛泛而谈
- 补强 `0003-switch-to-pnpm.md`，加入锁文件冲突和无效自依赖的具体知识
- 补强 `0004-build-svelte-app-shell.md`，加入 SvelteKit layout 边界和避免 route 巨石化的具体知识

## 关键知识

### 1. 协作规则如果不够具体，就很容易“看起来遵守了，其实没遵守”

像“写教程”这种规则，如果不继续限定质量，执行时就会自然退化成：

- 有文件
- 有标题
- 有改动描述

但没有真正的教学价值。

所以规则里要直接写：

- 至少 1 到 2 个具体知识点
- 必须和当前提交直接相关
- 不能只是 diff 改写

这是一种很实用的规则设计方法：  
不要只规定“要有这个东西”，还要规定“这个东西最低限度必须具备什么信息”。

### 2. 文档系统也需要回补，而不是只对未来生效

如果只更新 `AGENTS.md`，但不补旧教程，会出现一个断层：

- 新规则看起来是对的
- 但最近的历史记录仍然不满足新标准

所以这次顺手回补 `0003` 和 `0004`，本质上是在做一次文档一致性修复。

这和代码里的“补 migration / 补 test fixture / 补 data backfill”是同一种思路：

- 新规则建立后
- 历史数据也要尽量对齐
- 否则系统会长期带着不一致运行
