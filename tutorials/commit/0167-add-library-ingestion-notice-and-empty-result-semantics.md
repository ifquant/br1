# 0167 为导入基线补 notice 和空结果语义

## 这次改动做了什么

这一步执行的是 `01-03` 的核心部分：把导入基线的失败语义和可观察出口补起来。

具体做了两件关键事：

1. `LibraryImportActionResult` 不再只有 `cancelled` 和 `imported`
   - 现在新增了 `empty`
2. `library` 页面新增统一的 `libraryNotice`
   - 导入失败
   - Readest 迁移失败
   - 打开原文件失败
   - 导入结果为空

这些情况现在都会落到一个统一、可见的 notice 区域，而不是只在控制台里留一条日志。

## 为什么这一步重要

之前有一个典型问题：

- 用户点了导入
- 最后没有导入到书
- 页面上也没明显反馈
- 开发者只能去看 `console.error`

这会让“到底是取消了、没书、路径坏了、还是权限失败了”变得很难区分。

这次改完之后，最少能明确区分：

- `cancelled`
  - 用户取消，不算错误
- `empty`
  - 动作完成了，但没有导入到可用书籍
- `error`
  - 动作真的失败了，需要提示

## 你可以学到的工程知识

### 1. “空结果”不是“取消”

这是业务语义里非常容易混掉的一类问题。

比如：

- 文件选择器没选东西
- 和
- 选了东西，但最后没导进来

从代码看，很多时候都可能表现成“空数组”。

但从产品语义看，这两者完全不同：

- 取消：不需要打扰用户
- 空结果：通常应该给解释

所以这次把 `empty` 单独拆出来，是在修“语义模型”，不是在修一个小枚举。

### 2. 日志不等于失败处理

很多代码会这样写：

- `console.error('failed', error)`

这对开发者调试有帮助，但它不是完整的失败处理。

完整失败处理至少要回答：

- 上层能不能知道失败了
- 用户能不能看到结果
- 测试能不能断言失败语义

这次的 `libraryNotice` 就是在补第二层和第三层。
