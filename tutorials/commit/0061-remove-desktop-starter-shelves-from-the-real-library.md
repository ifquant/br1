# 0061：把桌面端假书架从真实 library 里拿掉

这次修的是一个很容易误导人的问题：桌面端 `library` 明明还没有真正导入书，但页面上却已经出现了几本“书”。它们其实只是前端样例数据，不是持久化书库。

这会带来两个坏结果：

- 用户会误以为“书库已经不空了”
- 迁移 `Readest` 的空态判断也会在心理上被干扰

所以这次把桌面端 `library` 改成只显示三类东西：

- `br1` 的真实持久化书库
- `Readest` 迁移入口
- 本机导入入口 / 空态

样例书架只保留给非桌面持久化场景，不再混进真实桌面书库。

## 改了什么

- 在 `/Users/dev/workspace2/hc_apps/br1/src/routes/library/+page.svelte`
  - 增加 `desktopLibraryMode`
  - 桌面端如果启用了持久化书库，就不再渲染 `starterBooks` 和 `starterImports`
  - 改为显示一个真正的空书库状态
- 这样页面会更诚实：
  - 有书就显示真实书
  - 没书就显示“空书库 + 导入 / 迁移”

## 这次值得学的两个知识点

### 1. demo 数据不能长期伪装成真实数据

在项目早期，样例数据很有用，因为它能帮你先把 UI 站起来。  
但一旦你已经接入真实持久化链路，就要尽快把 demo 数据移出真实主路径。

否则用户会分不清：

- 哪些是系统真的知道的书
- 哪些只是你为了占位先画出来的书

这类混淆会直接影响产品判断和调试判断。

### 2. “空态”本身就是产品逻辑的一部分

很多人把空态只当成一段文案，其实不是。  
空态决定了：

- 用户第一眼看到什么
- 系统在“还没有任何真实数据”时该给什么动作
- 数据导入 / 迁移 / 初始化链路是否自然

所以空态不是“等最后再补”的文案角落，而是数据产品的重要结构。
