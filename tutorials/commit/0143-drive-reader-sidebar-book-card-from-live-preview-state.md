# 0143: 让 reader sidebar 顶部书籍卡片显示真实阅读信息

## 这次改了什么

之前 sidebar 顶部的 `book chip` 只是一个占位块，只会显示：

- `当前阅读`
- `xx sections available`

这离 Readest 的书籍信息层还差很远，因为用户看不到当前到底在读哪本书、读到哪、积累了多少书签和笔记。

这一步只做一个小切片：

- 把 route 里已经有的 `currentPreview` 传给 `ReaderSidebar`
- 用真实的 `title / author / chapterLabel / progress / location / format / layout`
  驱动顶部书籍卡片
- 顺手把 `toc / bookmarks / notes` 的计数也挂上去

这样 sidebar 顶部终于不是纯占位，而是一个真正服务当前阅读状态的 book card。

## 为什么这一步不去新做一个 book controller

因为当前这些数据其实已经存在：

- `ReaderViewport` 会不断发 `readerstate`
- `reader/+page.svelte` 已经维护 `currentPreview`
- sidebar 只是之前没有消费它

所以这一步最合理的做法不是再发明一层 controller，而是直接把已有状态传过去。

这是一个很典型的工程判断：

- 如果只是“已有状态没被消费”，优先补消费链路
- 只有当状态来源混乱、推导逻辑分散时，才值得再抽 controller

## 这次实现上的关键点

### 1. 真实阅读状态和聚合统计是两类信息

顶部卡片现在展示两种不同来源的数据：

1. **实时阅读状态**
   - 标题
   - 作者
   - 当前章节
   - 进度
   - 位置
   - 格式 / 布局

2. **聚合数量**
   - 章节数
   - 书签数
   - 笔记数

这两类都和“当前这本书”有关，但更新节奏不同：

- 阅读状态可能随着翻页频繁变化
- 计数变化更慢

把它们同时放在一个 card 里，但逻辑来源保持独立，是比较稳的做法。

### 2. 空状态不要伪装成真实内容

这次加了一个 `hasOpenedBook` 判断。

如果当前还没真正打开书，就显示一条明确提示：

- “打开一本书后，这里会显示更完整的书籍信息。”

这比继续用模糊占位文案更稳，因为它不会让用户误以为当前看到的真的是书籍元数据。

## 这次能学到的编程知识

### 知识点 1：同一份状态，优先多处消费，不要重复生成

很多时候我们会下意识地在新组件里重新算一遍状态，或者再发明一套 store。

但如果上游已经有：

- 明确来源
- 明确生命周期
- 明确更新路径

那更好的做法通常是直接把它传过去。

这次的 `currentPreview -> ReaderSidebar` 就是这样。

### 知识点 2：做 UI 对齐时，优先补“信息密度”，再补装饰

Readest 看起来更成熟，不只是因为边距和颜色，而是因为：

- 同一块区域里承载了更有用的信息
- 用户不用切换上下文就能理解当前状态

所以这一步虽然看起来像视觉改动，本质上是在补信息结构，而不是单纯换样式。
