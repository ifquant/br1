# 0348 - 修正书库筛选按钮的文字挤压

这次修复处理的是一个纯视觉问题，但它直接影响书库的可扫读性：顶部筛选条里的按钮被压成了竖排文字。

书库页的第一任务是让用户快速找到下一本书。筛选条件本来应该像一排轻量标签一样被扫过，但修复前每个 pill 继承了通用按钮的固定宽度，中文标签只能挤在很窄的盒子里换行。结果用户第一眼看到的是一排竖向碎片，而不是“全部、在读、未开始、EPUB、PDF、标签”这些可理解的过滤条件。

## 改了什么

- `LibraryHeader` 里的 `.filter-pill` 显式恢复为自适应宽度。
- 筛选按钮的文字和计数都禁止被压缩换行。
- 活动筛选 chip 也覆盖了通用按钮和 `span` 的尺寸规则，避免后续出现同类竖排问题。
- 保留原有颜色、圆角和信息层级，只修正布局继承问题。

## 为什么不是重做筛选条

这不是一个需要重做交互模型的问题。筛选条的产品语义是成立的：状态、格式、归类、标签和当前摘要都在一个地方。

真正的问题是样式继承太宽：通用 `button` 给所有按钮设了 `28px` 固定宽度，通用 `button span` 又把内部文字容器固定成 `14px`。图标按钮需要这些规则，文字 pill 不需要。

所以这次只在筛选类组件上做局部覆盖：

- 图标按钮继续保持 28px。
- 筛选 pill 根据内容撑开。
- 移动端继续自然换行，不引入横向滚动。

## 一个小知识点

组件里的通用选择器很方便，但它会“顺手”影响同一组件里的所有后代元素。像 `button span { width: 14px; }` 这种规则适合图标按钮，却不适合文字按钮。

写组件 CSS 时可以先问一句：这个规则是在描述“所有按钮”，还是只是在描述“图标按钮”？如果答案是后者，就应该收窄选择器，或者像这次一样在文字按钮上显式覆盖。
