# 0721 - 在现有阅读器入口验证脚注

## 背景

`S2-R04C3` 对应 Readest `87f0240b0`、`b223ccaee`、`54aa20d4f`，
以及嵌套 foliate-js 的 `2bf0cecfc`。br1 没有使用 `FootnoteHandler`，
而是在 `ReaderViewport` 提取内容、由现有 Svelte 弹窗呈现。
因此这次迁移的是行为，不是另接一套弹窗引擎。

## 改动概览

- 无链接的厂商脚注标记按明确优先级读取文字：微信属性、掌阅属性、
  子图片 `alt`、标记自身 `alt`、点击元素 `alt`。普通图片不作为脚注。
- 普通链接统一走 Foliate 已解析章节路径的 `link` 事件，删除重复的
  单链接拦截。跨章节内容通过书籍的 `resolveHref` 和 `createDocument`
  读取，不在当前页寻找其他章节的同名 ID，也不创建第二个阅读 view。
- 数字标记先检查周围三层祖先中是否有至少两个其他数字链接，再验证
  目标结构。没有通过验证时调用现有导航入口，不显示空脚注。
- 新请求、页面位置清理、书籍替换和卸载使旧请求失效，防止异步结果
  覆盖新预览或触发过时导航。
- 纯文本由 Svelte 转义；HTML 预览克隆后连根节点一起过滤，原文不改写。

## 关键知识

1. `children.length` 只计算直接的元素子节点。上游的三个子元素限制仅用于
   一般的带链接容器，不限制 `li`、`aside`、`dt` 等专门分支，不能当作
   通用大小或安全限制。HTML 清洗仍是独立且必要的安全边界。
2. iframe 和宿主页面有不同的 JavaScript realm，宿主 `instanceof Element`
   可能拒绝真实书籍元素。克隆并包装节点既避免这种判断，也让清洗包含
   根节点。`alt` 只是文本，不能因其包含尖括号就进入 HTML 插入路径。
