# 0084 把 continue reading 收成更像主入口的 row

这次改动很小，但方向很重要：  
`继续阅读` 不再和主书架长得一模一样。

如果两个 section 都是同一种卡片网格，用户会更难感受到：

- 哪一块是“马上继续上次阅读”
- 哪一块是“完整书库浏览”

所以这次把 `继续阅读` 收成列表行，更像一个优先入口。

## 这次改了什么

文件：

- `/Users/dev/workspace2/hc_apps/br1/src/routes/library/+page.svelte`

### 1. `继续阅读` 固定走 `list` 视图

现在 `继续阅读` 渲染时显式传：

- `viewMode="list"`

这样它和下面的：

- `你的书库`

就不再是同一套视觉结构。

### 2. 把 view-mode 切换留给完整书库

`继续阅读` 作为主入口，不再共享完整书库的 grid/list 切换。  
切换逻辑继续只服务于：

- `你的书库`

这会让界面职责更清楚：

- `继续阅读` 是为了快速恢复
- `你的书库` 是为了浏览和管理

## 这次能学到的 2 个编程点

### 知识点 1：同一组件也可以承担不同信息层级

这里没有急着新拆一个组件，而是先让同一个 `BookshelfPreview` 用不同参数承担不同角色：

- `continue reading` 用 `list`
- `library` 用 `grid/list` 可切换

这是一种很常见的过渡手法：

- 先通过配置拉开层级
- 真有必要时再拆专用组件

### 知识点 2：不要把所有区域都绑到同一个 UI 状态

如果两个 shelf 共用同一个 `viewMode`，一个区域的交互就会改变另一个区域的语义。  
这会让界面越来越难懂。

更稳的做法通常是：

- 主入口区域固定表现
- 浏览区域保留更多可调状态

这次只先把它从“和主书架一样”改成“更像主入口”。
