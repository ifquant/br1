# 0740 - 在 GitHub README 中直接展示策略与故事动作

## 背景

用户需要访客打开 GitHub 首页就能看到动态效果，而不是本地 HTML、
模拟阅读器界面，或只对概念原画推拉镜头。每支媒体需控制在 512 KB 内。

## 主要目标

- 用波利比乌斯《历史》第三卷的坎尼会战，展示中央让步、两翼夹击、
  骑兵绕后的双重包围过程，优先让策略易懂。
- 用《青蛙王子》的城堡门口场景，展示青蛙到来、公主犹豫、开门接纳，
  通过实际动作表达兑现承诺。说明保留原作中父亲提醒的作用。

## 改动概览

- README 直接引用随仓库提交的动画；HTML 仅用于复现和暂停回看。
- 坎尼图使用固定镜头、移动阵形和路径；童话使用背景与独立角色动作。
- 编码器强制每个文件小于 512,000 字节；没有增加依赖或修改阅读器源码。
- 媒体说明区分原文、示意布局和改编；不宣称自动生成能力已经实现。

## 关键知识

1. GIF 可以在 GitHub README 内播放，但仓库 HTML 中的脚本不会执行。
   本地提交也不会自动更新 GitHub，需要推送到页面显示的分支后实测。
2. 固定背景让帧间差异集中在运动对象上，更容易兼顾动作连续性与小体积。
   编码可能合并相同的停留帧，所以总时长比编码后帧数更适合作为验收条件。
3. 排队中的动画回调可能携带早于重播时刻的时间戳，需要在共享时钟处
   限制负的经过时间，避免分镜索引变成负数。
