# 0083 把 continue reading 从主书架里去重

这次改动不涉及新的数据源，而是把同一批书在两个 shelf 里重复出现的问题收掉。

之前 `br1` 已经有了：

- `继续阅读`
- `你的书库`

但实现上，这两个区块其实都来自同一个 `importedBooks` 数组。  
结果就是：

- 最近读过的书先出现在 `继续阅读`
- 然后又在 `你的书库` 再出现一次

这会让首屏显得拥挤，也会削弱 `continue reading` 作为主入口的意义。

## 这次改了什么

文件：

- `/Users/dev/workspace2/hc_apps/br1/src/routes/library/+page.svelte`

### 1. 增加 `libraryShelfBooks`

现在除了：

- `continueReadingBooks`

又多了一份：

- `libraryShelfBooks`

它表示“完整书库里剩下的那些书”。

### 2. 用稳定 key 做去重

去重时优先用：

- `readerHref`

因为这更接近“打开目标”的唯一键。  
如果某本书还没有 `readerHref`，就退回：

- `title + author`

这样可以避免因为对象引用不同，导致同一本书仍然被重复渲染。

### 3. 主书架改成渲染去重后的结果

`你的书库` 不再直接用：

- `importedBooks`

而是用：

- `libraryShelfBooks`

这样首屏结构就更像真正的书库：

- 上面是“继续阅读”
- 下面是“其它书”

## 这次能学到的 2 个编程点

### 知识点 1：展示层派生数据，最好不要直接复用原数组

很多 UI 问题不是数据源错了，而是：

- 同一份原始数据被两个区域直接复用

这时更稳的做法不是去改源数据，而是派生出：

- “A 区要显示的数据”
- “B 区要显示的数据”

这样展示职责更清楚，也不会让一个区域的需求把另一个区域拖乱。

### 知识点 2：去重最好依赖稳定 key，不要依赖对象实例

如果用对象引用去重，很容易失败，因为：

- 同一条业务记录在映射后可能已经变成了两个不同对象

这时应该优先找：

- id
- href
- path

这类业务稳定键。  
实在没有，再退回组合键。
