# 0011 Tighten the library page to Readest-style grid rules

## 背景

之前 `br1` 的 library 还是一种“参考式重画”：

- 有比较大的 continue hero
- header 更像介绍区，不像真正的工具条
- 书架用了自适应网格

这会直接带来你指出的那个问题：  
**书籍页面大小不一。**

因为只要使用 `auto-fit + 1fr` 这类布局，卡片宽度就会跟着容器剩余空间浮动，视觉上很难接近 `Readest` 那种稳定、密排的书架感。

## 主要目标

- 把 library header 压成更像 `Readest` 的工具条
- 去掉影响密度的大块 hero
- 把书架改成固定卡宽、固定封面比例的规则
- 让第一版 library 更接近 `Readest` 的视觉秩序

## 改动概览

- 重写 `LibraryHeader.svelte`，从“大标题 + 操作区”改成“搜索条 + 小按钮工具条”
- 重写 `BookshelfPreview.svelte` 的网格规则：
  - 固定卡宽
  - 固定封面比例 `28:41`
  - 统一标题和状态信息密度
- 简化 `library/+page.svelte`：
  - 去掉 continue hero
  - 增加更轻的 summary strip
  - 保留两个书架分区，但整体更接近 `Readest` 的浏览型首页

## 关键知识

### 1. 想让书架“看起来齐”，关键不是调阴影，而是先锁定卡片宽度和封面比例

这次最重要的调整不是颜色，而是布局规则：

- 卡片宽度固定
- 封面比例固定为 `28:41`

原因很简单：

- 如果卡片宽度浮动，视觉基线就会漂
- 如果封面比例不固定，不同书的高度也会乱
- 一旦这两个变量不稳定，再好的边距和字体都救不回“书架秩序感”

所以做阅读器书架页时，一个很实用的优先级是：

1. 先固定卡宽
2. 再固定封面比例
3. 最后才调颜色、阴影、文案密度

### 2. `repeat(auto-fill, minmax(X, X))` 和 `repeat(auto-fit, minmax(X, 1fr))` 的视觉后果不一样

这次我们把书架从更自由的自适应网格，改成了更接近固定卡宽的写法。

它们的区别可以简单理解成：

- `auto-fit + 1fr`
  - 空间会被拉满
  - 卡片宽度会跟着容器变化
  - 更适合“响应式卡片面板”
- `auto-fill + 固定宽度`
  - 每张卡更稳定
  - 右边可能留下空白
  - 更适合“书架”这种强调秩序和重复节奏的界面

这也是为什么产品上看起来“只是差一点”，实现上其实是两种完全不同的布局哲学。

### 3. 严格对齐成熟产品时，要先删掉自己额外加的“大块情绪组件”

之前的 continue hero 不是坏设计，但它不是 `Readest` library 的核心形状。

如果目标是“严格对齐”，那像这种：

- 很占纵向空间
- 改变首屏重心
- 让页面更像 landing section 的东西

就应该优先删除。

这是一个很实用的迁移原则：

- 先对齐主结构
- 再考虑差异化扩展

不要在“还没对齐主骨架”时就加入很多自己的表达，不然最后会变成两边都不像。
