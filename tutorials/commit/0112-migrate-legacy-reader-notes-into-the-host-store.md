# 0112: 将旧版 reader notes 自动迁移到宿主 store

这次提交的目标不是新增 note 功能，而是避免升级持久化方式后，老用户误以为自己的笔记丢了。

之前 `reader` 的 notes 先存在浏览器 `localStorage`。后面我们把它提升到了桌面端宿主 store，这样每本书的笔记可以跟着 Tauri 的应用数据目录走，不再依赖浏览器临时状态。问题是，已经存在于 `localStorage` 里的旧笔记不会自动出现在新 store 里。

这次改动做了一个很小但很重要的迁移逻辑：

- 桌面端先尝试读取宿主 store
- 如果宿主 store 里这本书还没有 notes，再去读旧的 `localStorage`
- 读到旧笔记后，立刻写入宿主 store
- 写入成功后删掉旧的 `localStorage` 键

这样用户第一次升级后打开同一本书时，旧笔记会被自动搬过去，后续就只走宿主 store 这条正式路径。

## 这次学到的具体知识

### 1. 迁移代码最稳的模式，是“新存储优先，旧存储兜底”

不要一上来就无条件覆盖新存储。更稳的顺序通常是：

1. 先读新存储
2. 新存储为空时，再读旧存储
3. 只有旧存储真的有数据时，才执行迁移写入

这样可以避免把空数据写回去，或者把已经存在的新数据错误覆盖掉。

### 2. 一次性迁移完成后，要主动删旧键

如果迁移成功后不清掉旧键，后面很容易出现两个问题：

- 调试时不知道系统到底读的是哪一份
- 将来改回退逻辑时，旧数据又被误读回来

所以这种“只迁一次”的逻辑里，成功写入新存储后就删掉旧键，通常更干净。

## 这次实际改了什么

- 在 `reader/+page.svelte` 的 `loadNotes()` 里加入桌面端 notes 迁移逻辑
- 宿主 store 有数据时，直接用宿主数据
- 宿主 store 没数据时，自动检查并迁移旧 `localStorage`
- 迁移成功后清理旧键
