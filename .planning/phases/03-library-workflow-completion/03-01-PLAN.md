# 03-01 Plan: 完成 continue reading 和最近阅读的产品化分区

**Phase:** 3 - Library Workflow Completion  
**Plan:** 03-01  
**Status:** Planned  
**Requirements:** LIB-04  
**Depends on:** 02-03  
**Parallel-safe:** No  

## Why This Plan Exists

`library` 页面现在已经有了第一版 `continue reading`，但它仍然更像功能雏形，而不是 `Readest` 那种稳定、明确、可预期的产品分区。要进入后续 reader parity，必须先把书库首页最核心的“回到正在读的书”这条工作流收成正式规则。

## Brownfield Context

当前已有实现：

- `ContinueReadingShelf.svelte`
  - 已有 continue reading 行式展示
  - 已有详情展开、原文件入口、从头开始入口
- `library/+page.svelte`
  - 已按 `lastOpenedAt` 提取 continue reading
  - 已把搜索态压平成单一结果集

当前问题：

1. continue reading 与“最近阅读”还没有真正的产品边界
2. section 数量、条目数、排序规则仍偏实现导向
3. 空态、已完成书籍、未开始书籍的展示规则还未完全固定

## Scope

In scope:

- 固化 continue reading / 最近阅读的 section 规则
- 明确条目上限、排序优先级和已完成条目的处理
- 收空态、无阅读记录时的降级表现

Out of scope:

- reader 内部恢复精度
- 新增复杂分组或云同步
- 搜索缓存和高级筛选

## Deliverables

1. 更稳定的 continue reading / 最近阅读 section 规则
2. 条目状态、数量和空态都更接近 `Readest`
3. library 首页的主工作流不再显得像临时拼接

## Execution Plan

### Wave 1: 固化 section 语义

1. 审计 `continue reading` 和主书架的边界
2. 定义“最近阅读”条目是否独立存在，以及和 continue reading 的关系
3. 明确已读完、未开始、刚导入条目的归属规则

### Wave 2: 收口条目排序和数量

1. 收口 continue reading 的最大展示数量
2. 固化最近阅读的排序规则
3. 明确 section 在浏览态/搜索态中的保留或隐藏逻辑

### Wave 3: 收口空态和降级表现

1. 没有阅读记录时的 section 表现
2. 全部已读完或全部未开始时的降级逻辑
3. 如有必要，补 focused smoke 断言

## Verification Checklist

- `pnpm check`
- `pnpm exec playwright test tests/e2e/library-smoke.spec.ts`
- `git diff --check`
- 手工 library section 复审

## Done When

1. continue reading / 最近阅读不再依赖“当前实现刚好这样”
2. 用户能稳定理解 library 首页最上方内容为什么会出现
3. section 规则可以直接作为后续 reader 状态回流的输入层

## Not Planned Here

- 不处理 locator/CFI 级位置恢复
- 不处理 reader 内工作区
- 不处理 Readest 数据兼容的更深细节
