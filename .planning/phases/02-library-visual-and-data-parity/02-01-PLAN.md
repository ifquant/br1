# 02-01 Plan: 对齐书库顶部工具条和搜索行为

**Phase:** 2 - Library Visual and Data Parity  
**Plan:** 02-01  
**Status:** Planned  
**Requirements:** LIB-02, LIB-03  
**Depends on:** Phase 1  
**Parallel-safe:** No  

## Why This Plan Exists

`library` 页面的第一眼差异主要集中在顶部区域：搜索框、工具按钮、信息密度和交互语义。当前 `LibraryHeader.svelte` 还是一个只读壳层，搜索框是占位输入，按钮也是静态 preview。要继续往 `Readest` 靠，最合理的第一刀不是先改书架卡片，而是先把顶部工具条和搜索语义定下来，因为这会决定后面书库筛选、排序、导入入口和滚动布局的组织方式。

## Brownfield Context

当前已有实现：

- `src/lib/components/library/LibraryHeader.svelte`
  - 已有搜索外观和三枚顶部动作按钮
- `src/routes/library/+page.svelte`
  - 已有 `import`、`Readest` 迁移、`grid/list` 视图切换和 notice 状态
- `src/lib/components/library/BookshelfPreview.svelte`
  - 自己还带着局部 view-mode 工具条

当前问题：

1. 顶部 header 和书架内部工具条分裂，信息层重复
2. 搜索框只是 placeholder，没有真正绑定书库状态
3. 导入、更多菜单、library view 切换还没有清晰地归位到 `Readest` 式顶部工具层
4. 视觉上接近，但产品语义还没有统一

## Scope

In scope:

- 对齐 library 顶部 header 的视觉结构和动作归属
- 将书库搜索从只读壳层升级成真实的 library filter 入口
- 决定 `grid/list`、导入入口和顶部按钮的归位方案
- 为后续 `02-03` 的排序/筛选行为建立顶部交互基础

Out of scope:

- 书籍卡片视觉细节
- continue reading 分区产品化
- reader 打开协议
- 更深的书库排序策略

## Deliverables

1. 一个不再只是 preview 的 library 顶部工具层
2. 真实可用的书库搜索入口
3. 顶部工具条与书架内部工具的职责边界
4. 至少一条验证顶部搜索/动作层的回归

## Execution Plan

### Wave 1: 收敛顶层信息架构

1. 明确哪些操作应该在 header
   - 搜索
   - 导入
   - 视图切换
   - 更多菜单
2. 明确哪些操作不应继续留在 `BookshelfPreview`
3. 对照 `Readest` 确认顶部区域的视觉密度和按钮顺序

### Wave 2: 让搜索变成真实行为

1. 把 search input 变成真实可编辑状态
2. 将 query 绑定到 `library/+page.svelte`
3. 让书架内容对 query 产生实时过滤
4. 保持 desktop / web 都能工作

### Wave 3: 清理重复工具层

1. 减少 `BookshelfPreview` 顶部工具的职责
2. 避免同一个动作在 header 和 shelf 里都存在
3. 确保顶部工具层成为真正的 library control surface

1. 顶部 search / action bar 成为真实可用入口
2. library 搜索开始影响实际书籍展示
3. 顶层工具归属比当前更接近 `Readest`

## Not Planned Here

- 不处理卡片视觉和封面比例
- 不处理 continue reading 和 library data flow
- 不处理更深的排序/筛选模型
