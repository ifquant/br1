# 02-03 Plan: 对齐书库排序、筛选和滚动行为

**Phase:** 2 - Library Visual and Data Parity  
**Plan:** 02-03  
**Status:** Planned  
**Requirements:** LIB-03  
**Depends on:** 02-01, 02-02  
**Parallel-safe:** No  

## Why This Plan Exists

当顶部工具和卡片视觉都更像 `Readest` 后，剩下最容易露馅的是行为层：书架里到底按什么顺序排、搜索后如何筛、grid/list 切换是否保留上下文、滚动容器和滚动条行为是否像 `Readest`。当前 `library/+page.svelte` 已有一版按最近打开/格式/导入时间排序的逻辑，但还没有完整收口成正式的 library behavior model。

## Brownfield Context

当前已有实现：

- `library/+page.svelte`
  - 已有 `sortRecordsForLibraryShelf()`
  - 已有 `grid/list` 视图状态
  - 已接入 `OverlayScrollbars`

当前问题：

1. 当前排序更像“工程上方便验证”，未必完全等于产品排序
2. 搜索、排序、continue reading、library shelf 的关系还没有完全理顺
3. 滚动容器虽然已接入，但 library 整体滚动体验还未正式验收
4. 筛选行为目前仍然偏轻，尚未定义 library view 的稳定规则

## Scope

In scope:

- 审视和收敛 library 主排序规则
- 定义搜索后的书架筛选表现
- 收口 grid/list 切换后的内容组织
- 复审滚动容器和滚动条行为

Out of scope:

- continue reading 的独立产品层
- 更深的 reader 路由或恢复逻辑
- 新增复杂多条件筛选面板

## Deliverables

1. 更明确的 library 排序/筛选行为模型
2. 搜索和书架 section 的更稳定关系
3. 滚动行为与 `Readest` 更接近的复审结果

## Execution Plan

### Wave 1: 收敛排序与筛选语义

1. 审计当前排序规则是否仍适合作为正式行为
2. 定义搜索 query 如何影响：
   - continue reading
   - library shelf
   - 空态
3. 明确 grid/list 切换是否应保留当前过滤上下文

### Wave 2: 收敛滚动体验

1. 复审 `OverlayScrollbars` 在 library 页的表现
2. 调整容器层级，避免看起来像额外包裹层
3. 确认桌面端滚动条行为更贴近 `Readest`

### Wave 3: 形成验证护栏

1. 保留至少一条 web smoke
2. 如行为变动明显，补 focused regression
3. 手工复审排序/滚动是否已达到视觉层通过标准

## Verification Checklist

- `pnpm check`
- `git diff --check`
- `pnpm exec playwright test tests/e2e/library-smoke.spec.ts`
- 如需要：focused desktop/manual library behavior check

## Done When

1. library 排序、搜索、视图切换和滚动行为不再显得是临时规则
2. section 组织和过滤逻辑更接近 `Readest`
3. 滚动体验在桌面端不会成为明显差异点

## Not Planned Here

- 不继续扩展 continue reading 工作流
- 不处理 reader 页面能力
- 不引入复杂筛选系统
