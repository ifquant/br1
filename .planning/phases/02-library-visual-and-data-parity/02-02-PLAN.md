# 02-02 Plan: 对齐书库卡片、封面、元数据与状态展示

**Phase:** 2 - Library Visual and Data Parity  
**Plan:** 02-02  
**Status:** Planned  
**Requirements:** LIB-02  
**Depends on:** 02-01  
**Parallel-safe:** No  

## Why This Plan Exists

当顶部工具层开始稳定后，`library` 页面和 `Readest` 最直观的差距就落在书籍卡片本身：封面比例、标题换行、作者/进度/状态的信息层级、操作图标的存在方式，以及 grid/list 两种视图下的信息压缩方式。当前 `BookshelfPreview.svelte` 已经有一版卡片，但仍然带有 bridge 过渡态，信息密度和视觉秩序都没有完全贴近 `Readest`。

## Brownfield Context

当前已有实现：

- `BookshelfPreview.svelte`
  - 已支持 grid/list 两种卡片
  - 已有封面 fallback、标题/作者/状态行
- `ContinueReadingShelf.svelte`
  - 已有更高密度的行式展示
- `library/+page.svelte`
  - 已经把真实 library record 映射成 `LibraryShelfBook`

当前问题：

1. 书籍卡片的元数据层级还比较“组件视角”，不是 `Readest` 的产品视角
2. 封面比例和卡片空间分配仍然不够贴近 `Readest`
3. grid/list 的视觉语言还不够统一
4. 某些状态仍然更像调试字段，而不是正式书库状态信息

## Scope

In scope:

- 对齐 grid/list 卡片的封面、标题、作者、状态、进度、操作图标
- 清理卡片上的过渡性 copy 和 bridge 痕迹
- 调整元数据字段的展示优先级
- 让导入 tile 与真实图书卡片的视觉关系更接近 `Readest`

Out of scope:

- 顶部搜索和工具条逻辑
- continue reading 的独立产品策略
- 更深的排序和筛选规则
- reader 页面的视觉差异

## Deliverables

1. 更接近 `Readest` 的书籍卡片视觉层级
2. grid/list 视图下更统一的元数据语义
3. 导入 tile 与正式卡片之间更合理的视觉关系

## Execution Plan

### Wave 1: 对齐信息层级

1. 明确卡片上最重要的信息顺序
2. 去掉调试感强的文案和临时状态
3. 对齐 `Readest` 的标题/作者/状态密度

### Wave 2: 对齐封面与卡片结构

1. 收敛封面比例和留白
2. 收敛 grid/list 视图中的结构差异
3. 调整 hover / action icon 的表达方式

### Wave 3: 收口导入 tile

1. 让导入 tile 在视觉上不再像“特殊组件”
2. 与真实书籍卡片保持一致语言
3. 保留导入入口的可发现性

## Verification Checklist

- `pnpm check`
- `git diff --check`
- 手工 library 视觉复审
- 如需要：更新或补 web smoke 文案断言

## Done When

1. 书籍卡片一眼看上去更像 `Readest` 而不是过渡 UI
2. grid/list 两种视图有一致的产品语义
3. 元数据字段不再显得像调试输出

## Not Planned Here

- 不处理顶层工具条和搜索逻辑
- 不处理 continue reading 的更深工作流
- 不处理排序/筛选/滚动行为
