# 04-01 Plan: 稳定 EPUB 打开链路与正文渲染

**Phase:** 4 - Reader Open Pipeline and Format Base  
**Plan:** 04-01  
**Status:** Planned  
**Requirements:** RDR-01, FMT-01  
**Depends on:** 03-03  
**Parallel-safe:** No  

## Why This Plan Exists

当前 `br1` 的 reader 已经能在部分路径上打开 `EPUB`，但打开链路仍混有样书时代残留、临时兜底和不完全透明的 `foliate-js` 接入方式。要进入后续 reader 结构和视觉对齐，必须先把 `EPUB` 作为主格式稳定下来。

## Brownfield Context

当前已有实现：

- `library-file -> reader` 桌面独立窗口链路已存在
- `foliate-view` 已能在部分真实书籍上渲染正文
- `library` 已能把恢复位置、continue reading、最近阅读回流到书库
- 已有 focused desktop regression 覆盖部分 `EPUB` 打开和恢复路径

当前问题：

1. `EPUB` 打开链路仍存在 bridge/fallback 历史分支，排障成本高
2. `foliate-js` book/document/render target 之间的职责边界不够清楚
3. 某些 `EPUB` 仍可能出现正文未进入主舞台、恢复位置异常或隐式降级

## Scope

In scope:

- 梳理并收口 `EPUB` 打开入口、book document 生成和正文挂载链路
- 减少样书逻辑、临时 fallback 和不透明 guard 对主路径的干扰
- 补强 `EPUB` 正文渲染和恢复位置的 focused regression

Out of scope:

- `PDF` vendor / wasm
- reader 视觉对齐
- 笔记、书签、搜索的更深行为层

## Deliverables

1. 更清晰的 `EPUB` 打开主路径
2. 更稳定的正文渲染与恢复位置行为
3. 针对真实 `EPUB` 的桌面自动化护栏

## Execution Plan

### Wave 1: 审计 EPUB 打开链路

1. 盘点 `asset` / `library-file` 两条 `EPUB` 打开入口
2. 梳理 `loadReaderBookDocument()`、`makeBook()`、render target 的职责边界
3. 标出仍属于临时 bridge/fallback 的分支

### Wave 2: 收口主路径

1. 去掉不再需要的样书时代分支和临时状态
2. 统一 `EPUB` 的 book/document/open/render 流程
3. 让失败模式更明确，而不是静默掉到白屏或不透明空态

### Wave 3: 验证正文与恢复行为

1. 跑现有 `EPUB` focused desktop regression
2. 必要时补一条专门断言正文可见 + 恢复定位可用的回归
3. 记录已知仍未覆盖的 `EPUB` 边界

## Verification Checklist

- `pnpm check`
- `pnpm exec wdio run wdio.conf.ts --mochaOpts.grep '<EPUB focused tests>'`
- `git diff --check`
- 手工桌面打开至少一本真实 `EPUB`

## Done When

1. `EPUB` 能稳定进入 reader 主舞台
2. 主路径不再依赖样书或不透明 fallback
3. 自动化能覆盖至少一条真实 `EPUB` 打开与恢复路径

## Not Planned Here

- 不处理 `PDF`
- 不处理 reader 视觉布局
- 不处理 service 型能力
